RUNNING COMMAND WINDOW
One protected transcript ends in the editable >> prompt only when ready. During
pending work it ends in Running… (Ctrl+C to stop), and the dock title shows Running.
It stays scrollable/selectable, with Copy in its context menu, but accepts no new
command input. An unsubmitted draft is hidden and preserved during ordinary work.
Ctrl+C during work, including with editor/console text selected, requests cancel
through Studio's existing atomic token. Stopping replaces Running, and repeated
presses do not submit commands or produce additional prompts. Stop/Shift+F5 uses
the same cancellation path. A ready prompt returns after the latest worker result,
including errors/cancel, never merely because cancellation was requested.
Idle Ctrl+C preserves the existing selection-copy/abandon-input behavior.

Cancellation is cooperative, not arbitrary thread termination. In native PDE
reaction evaluation or on-demand JIT, the shared cancellation token classifies
the resulting exception as R1006/Cancelled, preserving transactional workspace
rollback. Genuine PDE validation/evaluation failures remain R2100. Ordinary output
is black; diagnostic red ranges and clickable locations remain intact.

INLINE SOURCE RENAME
Project Rename Source or F2 edits the selected source item in place, selecting its
basename. Enter/focus completion uses the existing safe rename service after Qt
has closed its editor; Escape cancels. An extension-free filename retains .p.
Only filenames in the same folder are accepted by this UI. Unsafe names, collisions
and project changes reject with nonmodal feedback. The service retains filesystem/
manifest rollback, dirty-document contents, tab identity and external-change
protections. Tree double-click still opens sources. Root/folder rename is unchanged.
