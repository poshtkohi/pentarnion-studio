L23. NATIVE ODE MODELS AND SOLUTIONS (ADDITIVE PROFILE0.2 EXTENSION)
ode flow(t, pentarnion p; real a, pentarnion b) {
    p' = b*p-a*p;
}
solution s = odesolve(flow, p=p0, a=damping, b=B,
    t0=0,t1=20,sample_step=0.01,method="bdf",
    jacobian="analytic",rtol=1e-8,atol=1e-10);

Time is the first untyped identifier and has real type inside the block. Each
state before ';' and parameter after ';' has an explicit real/pentarnion type.
The parameter section may be omitted or empty. There must be at least one state.
Every state has exactly one derivative assignment; equation order is immaterial.
No local declarations, loops, branches, calls to user code, nested solves or side
effects occur in an ODE body. No workspace values are implicitly captured: only
time, declared states/parameters and read-only basis names are visible. Local
names are unique and cannot collide with protected names. State/parameter names
also cannot collide with solver option names.
A state named t is disallowed because s.t is reserved for sampled output times.
ODE model names cannot be reassigned. A solution variable may receive a later
solution, with its checked named-state schema updated to match.

odesolve names an earlier ODE model, then explicitly supplies every state initial
value, parameter value and t0/t1 using unique named arguments. Type widening is
integer->real->scalar Pentarnion; no implicit narrowing. All supplied values are
evaluated once before integration and remain fixed throughout that solve. Time
arguments may appear within the RHS. The immutable A_gamma_v1 context applies.

Options: t0,t1 required finite reals with t1>=t0; equality returns the initial
state only. sample_step positive (default.01);
method is a literal "bdf" (default), "adams", "erk" or "esdirk";
jacobian is a literal "analytic" (default) or "finite_difference";
rtol in (0,1), default 1e-7; atol>0, default 1e-9. Absolute tolerance is a scalar
applied to every real coordinate. All methods use native SUNDIALS integration:
  "bdf": CVODE backward differentiation, variable order 1-5, for stiff systems.
  "adams": CVODE Adams-Moulton, variable order 1-12, for nonstiff systems.
  "erk": ARKODE Dormand-Prince 5(4), seven-stage explicit Runge-Kutta.
  "esdirk": ARKODE ESDIRK4(3)6L[2]SA, six-stage implicit Runge-Kutta.
The embedded pairs use adaptive step sizes; the principal solution orders are
5 for erk and 4 for esdirk. Explicit erk is intended for nonstiff systems;
esdirk is intended for stiff systems. There is no automatic method switching.
Solver settings never select an interpreted model fallback.
sample_step controls returned samples, not adaptive internal timesteps. Include
t0 and the exact final endpoint t1 even when the interval is not a multiple of
sample_step. Reject spacing that cannot produce distinct finite binary64 times.

Optional resource limits: max_steps positive integer<=100000000 (default1000000),
max_samples positive integer<=1000000 (default1000000), max_seconds in (0,3600]
(default60, integration only). All failures stop the request with a diagnostic;
no partial trajectory is published as a complete solution. Stop cancellation
terminates compilation/integration and preserves the pre-request workspace.

Supported RHS subset: ordered +,-,*, unary signs, explicit groups; division by
real scalar only; ^ with a literal integer exponent0..64; pent constructors;
conj,scalar,pure,norm2,coeff with literal index0..4; commutator,associator; real
sin,cos,tan,exp,log,sqrt,sinh,cosh,tanh. Reject unsupported calls/operations before
compilation. Whole-Pentarnion elementary functions and equation division retain
their ordinary interpreter meanings outside ODEs but are not native RHS features
yet. Domain failures and nonsmooth/undefined derivatives are errors, not guessed
Jacobians. Gamma stays in [0,1]. Preserve all multiplication order and Group nodes.

Limits:64 real state coordinates,128 real parameter coordinates,20000 RHS nodes.
One real state occupies1 coordinate, one Pentarnion5. Bound each solution to8m
sampled state coordinates. Bound unique retained solution data across the command
workspace to8m state coordinates, counting aliases once; at most64 solves/request.
Project schema_version remains1. Checking, opening, editing and saving do not
compile or run equations. Only explicit execution invokes the native backend.

L24. COMPILER-EMITTED JACOBIANS AND STRUCTURAL NATIVE CACHE
The compiler always generates native RHS and full real-coordinate Jacobian
entry points. Analytic mode uses forward automatic differentiation of the same
grouping-preserving real coordinate computation, with no finite differences.
For n Pentarnion states, the Jacobian has5n rows/columns (plus any real states).
No user-written Jacobian is accepted or required. This is the state Jacobian
df/dy; automatic parameter sensitivity trajectories are a future feature.
For bdf/adams/esdirk, finite_difference mode requests the selected SUNDIALS
integrator's dense difference-quotient Jacobian. The explicit erk method accepts
either jacobian option for source compatibility, but does not evaluate a Jacobian;
its solution summary reports jacobian=not_used. The compiler still emits the same
RHS/Jacobian entry points. Changing method or Jacobian mode does not recompile the
generated native model.

Compile standalone C++20 model code into DLL on Windows/shared library on Linux.
Use the configured CMake compiler directly with argument lists and cancellation/
timeout handling, never a user-provided shell command. Both model functions have
a narrow C ABI; Qt/Eigen/SUNDIALS do not cross the generated-model interface.
Store generated source, atomic manifest and compiled artifact in an ignored
.penta-cache/odes directory beside the project manifest, or beside a standalone
source. The bare projectless console uses application-local storage. No project
manifest rewrite is required, and cache entries are platform/toolchain specific.

Fingerprint the typed ordered model, state/parameter layout, generated support
code, algebra/backend identity, configured compiler identity and target ABI.
Exclude source spans/comments/whitespace, external parameter values, initial
values, gamma values and integrator/output settings. Changing an embedded literal
or equation structure generates a new kernel. Source/binary hashes and ABI are
checked on reuse; incomplete/corrupted artifacts are regenerated under a
cross-process lock. Never reuse a stale incompatible artifact on compiler error.
display(s) reports sample/coordinate counts, cache hit/miss/key, Jacobian mode and
step count. First execution compiles; later executions reuse valid binaries.

L25. SAMPLED SOLUTIONS AND CURVE PLOTS
solution is an immutable sampled ODE result, distinct from a Pentarnion scalar.
s.t is a real-valued time series. s.<state> is a real or full five-coefficient
Pentarnion series according to the declared state type. Unknown members fail
static checking. Members are read-only views sharing the result data. There are
no indexing into solution series or declared general series types in this
extension. Separate dense arrays and their scalar indexing are defined in L30.
coeff(s.p,k), k integer0..4, extracts a real series from a Pentarnion series.
display(s) gives a compact summary; it does not dump millions of sample values.

plot(xSeries,ySeries); requires two real series with equal sample counts and
draws their paired coordinates as a connected 2D curve with generic x/y axes.
plot2("i","j",s.p); plot3("1","i","j",s.p); project complete Pentarnion
samples into connected curves. Existing individual Pentarnion arguments remain
origin-to-endpoint arrows. Canonical projections preserve equal coordinate units;
generic x/y plots scale each axis independently and use a bottom/left frame. Preserve requested sample order
and points; no automatic point thinning, smoothing, arrows at every point, or
interpolation of mismatched series. At most256 curves and1m curve points/request;
the GUI additionally bounds retained curves to2m points and128 allocated
subplot panels across all figures. Plot replacement affects only the
active subplot, preserving its annotation overrides and all other panels.

L26. MATLAB-STYLE SUBPLOTS
subplot(rows,columns,index); uses positive Integer dimensions and a1-based
row-major index: subplot(2,2,3) selects the bottom-left panel. At most64 cells in
one grid. It operates inside the current figure, creating one if needed, and is
distinct from tilefigures, which arranges entire figures. Re-selecting a panel
preserves its data, labels and camera. Title/xlabel/ylabel/zlabel/caption target
the active panel. Figure Name/NumberTitle and docking remain figure properties.
Changing grid dimensions repositions retained numeric panels; a smaller grid
that would discard populated panels fails without mutation (use clf first).
clf clears all panels and returns to one empty1x1 canvas while retaining figure
identity/name. close removes the entire figure. Figure export captures all
allocated panels and their labels in PNG, JPEG or SVG. The Save icon in an
individual subplot exports only that panel. Export behavior is defined in L29.
Scalar-only three-argument subplot is supported; spanning indices, compact
subplot(221), subplot handles, hold and general graphics-object APIs are deferred.

L27. MONOTONIC ELAPSED-TIME MEASUREMENT
tic; and tic(); start/restart the execution session's default timer.
toc; and standalone toc(); print "Elapsed time is <seconds> seconds." without
resetting it. toc() within an expression returns a nonnegative real elapsed
time, without printing itself, for example real elapsed=toc(); display(elapsed);
Use steady monotonic wall-clock time, in seconds; no calendar-clock subtraction.
The most recent tic wins. There are no timer handles, nested stacks or arguments.
Calling toc before tic is a runtime error R1811, never a fabricated zero.

The timer persists across direct Command Window submissions. clear/clc preserve
it; Reset Workspace and fresh Run File reset it. Cancellation rolls timer state
back together with workspace state. Static checking, opening/saving/editing do
not start/read timers. tic/toc are protected builtins only in profile0.2;
legacy0.1 identifier compatibility is preserved. Timing inside ODE bodies is
unsupported, so RHS/Jacobians stay pure and reproducible.

tic around odesolve measures execution wall time after subtracting time spent
in the native compiler process, even on a first cache miss. Cache lookup, model
preparation and integration remain included. GUI drawing occurs after worker
evaluation and is not included in a timer stopped inside the script. Across
console commands, elapsed wall time includes pauses at the prompt.

timer_stmt = ("tic"|"toc"),["(",")"],";" ;
call additionally admits toc() as a zero-argument Real-returning builtin outside
ODE bodies. Bare toc is a command, not a value-expression form.

L28. INTERACTIVE PLOT TOOLS AND DISPLAY QUALITY
This is a GUI extension. No new .p grammar, smoothing function or numeric type is
introduced. Existing plot/plot2/plot3/subplot statements keep their mathematical
meaning. The data renderer uses anti-aliasing to improve raster line edges;
stored sample values, sample order, finite extrema and polyline vertices are
preserved. Curves remain connected stored samples, without fitted splines,
averaging, discarded peaks, resampling or changes to ODE tolerances.

Each allocated subplot has an icon toolbar with tooltips and accessible button
names. Zoom in/out select a click mode; click the canvas to zoom around that
position. Wheel zoom is available. Pan uses a left-button drag. Rotate is enabled
only in 3D. Reset/Fit restores the full finite data range and refreshes camera
clipping. View tools and sample-marker visibility belong to each subplot and
survive subplot selection, resizing, docking and figure tiling. Toolbar actions
activate their own subplot. Interaction does not mutate the command workspace.

Data Cursor snaps to the nearest visible original stored sample in screen space,
within a bounded logical-pixel radius. The selected tip shows its curve label,
one-based sample index and original x/y(/z) numeric coordinates, independent of
render normalization. It never reports an interpolated point along a segment as
a saved sample. Show Points toggles markers at the actual curve vertices and
does not change the connected line or sample count. Replacing/clearing the plot
clears the selection; Escape clears a tip without changing samples. One selection
per subplot is retained. Large coordinates
remain numerical values, not raw GPU-world normalized numbers.

PNG/JPEG exports include the anti-aliased native plot, mathematical labels and
visible data annotations. SVG is also supported, as defined in L29. Subplot
controls themselves are not part of the exported image.
Zoom/pan may intentionally move data outside the plot rectangle; Reset/Fit
recovers the complete view. These are view controls, not data correction tools.

L29. SVG AND INDIVIDUAL SUBPLOT EXPORT
The figure toolbar's Export Image command saves the entire selected figure,
including every allocated panel. Each subplot has its own Save icon with the
tooltip "Save subplot..."; it activates that figure/panel and opens a Save dialog
for only that panel. Both routes support .png, .jpg, .jpeg and .svg. No new .p
export statement or general filesystem-writing capability is introduced.

PNG/JPEG use the native framebuffer. SVG exports projected vector curves,
arrow geometry, axes, sample markers and text/math glyph paths. It preserves the
current camera, viewport, clipping, labels, legend and visible data annotations;
it is not a whole-scene raster image embedded in an SVG wrapper. Subplot toolbar
icons are omitted. Individual-panel export contains no neighboring panel or
figure toolbar. Dense sampled curves can produce large SVG files because their
computed vertices are retained. Export never changes the numerical samples.

SVG uses painter depth ordering for projected 3D geometry; it is not an OpenGL
depth-buffer capture. PNG/JPEG remain available when an exact rasterized view
is wanted. No general transparent 3D scene-export API is introduced.

Export is explicit and requires a usable native view. It works for docked,
tiled and floating figures. Cancel/invalid targets/unavailable contexts or
encoding/write failures do not replace an existing destination. Unicode paths
and QSaveFile atomic writes apply to every format. Reset/Fit before saving when
the complete data range is wanted; zoom/pan intentionally affect the saved view.

L30. REAL AND PENTARNION MATRICES AND VECTORS
This additive language 0.2 extension provides dense two-dimensional arrays.
Scalars and arrays remain distinct types, even for a 1-by-1 matrix. A Pentarnion
scalar is still one algebra element with five coefficients; a vector declaration
below means a row or column array of real or Pentarnion elements.

matrix A = [1,2;3,4];          % infer realmatrix from scalar entries
vector v = [1;2];             % row/column shape checked at runtime
matrix y = A*v;               % matrix by column vector
matrix P = [i,j;k,ell];       % infer pentarnionmatrix
realmatrix R = zeros(2,3);    % explicit real element type
pentarnionmatrix Q = [1,i];   % real entries embed into Pentarnion scalars

matrix/vector declarations infer the array element type from the initializer.
realmatrix and pentarnionmatrix are explicit aliases. Assignment preserves that
declared element type; real arrays may widen when assigned to a Pentarnion array. A scalar
initializer cannot silently become a 1-by-1 matrix; write [value] explicitly.
vector validates row/column orientation when declared; it uses the same matrix
value type and operations thereafter. A vector-valued result of * remains an
array, including a 1-by-1 result from a row-vector/column-vector product.

Literal columns are separated by commas or whitespace, and rows by semicolons
or newlines. All rows must have the same length and entries must be numeric
scalars. Nested array concatenation, range expansion, string/object entries and
implicit multiplication are unsupported. [] is the 0-by-0 real matrix. In a
literal, [1 -2] has two entries; [1 - 2] has one subtraction expression. Group
expressions when spacing could be ambiguous. Existing pent([a,b,c,d,e]) remains
the five-coefficient scalar constructor, not a matrix constructor.

A(row,column) and A(index) use positive Integer indices starting at 1. Linear
indexing is column-major: for A=[1,2;3,4], A(2) is 3. Bounds are checked at runtime.
A(1,2)=value; assigns one compatible scalar element without changing the shape.
Indexed writes preserve aliases as immutable prior values. Colon/slice/logical
indexing, end, array resizing/deletion and multiple-index arrays are deferred.

Operators:
  A+B, A-B: equal-size arrays, or a scalar broadcast over every array entry.
  A*B: matrix product when both operands are arrays; columns(A)==rows(B).
       Compatible matrix/vector, row/column and outer products use this same rule.
       If one operand is scalar, * applies it on that same side of each entry.
  A.*B: elementwise ordered products; equal array shapes or one scalar broadcast.
  A./B: elementwise division; divisor entries must be real, with nonzero values.
  A/realScalar: real scaling. Matrix right/left division and equation solves are deferred.
  A.^B: elementwise powers; real scalar/matrix exponents. Pentarnion bases need
        integer exponents (Integer scalar, or checked integer-valued real entries),
        within this array extension's bound -100,000..100,000.
        Matrix ^ is not supported. The existing scalar ^ rule remains unchanged.
  +A, -A: entrywise signs.

Binary matrix products use sum_k A(row,k)*B(k,column), preserving operand order.
No associativity is assumed for Pentarnion matrices. Parenthesize chains with
three or more Pentarnion operands, e.g. (P*Q)*R or P*(Q*R), as for scalar products.
No determinant, matrix inverse, dot/linear solve or spectral operation is added;
inv(p) keeps its existing scalar Pentarnion meaning.

transpose(A) and A.' transpose without conjugation. A' transposes and conjugates
each Pentarnion entry. Real conjugation leaves values unchanged. conj(A),
scalar(A), pure(A), norm2(A) and coeff(P,k) operate entrywise; coefficient k is
still 0..4 and coeff returns a real matrix with the same shape. The five whole
Pentarnion functions sin/cos/exp/sinh/cosh also apply entrywise to arrays. The
remaining one-argument real functions (sqrt, tan, asin, acos, atan, tanh, asinh,
acosh, atanh, log, log10, log2, abs, floor, ceil, round) accept real arrays only.
Their existing domain/finite checks apply to every entry. atan2 arrays are deferred.

plot(x,y) and plot3(x,y,z) accept real row/column vectors or sampled real series.
Coordinate arguments must have equal element counts; full 2D matrices are not
flattened into curves. Existing plot2/plot3 with literal canonical axis names
still projects individual Pentarnion scalars or sampled Pentarnion trajectories.
General matrix-based Pentarnion projection plotting is deferred.

Matrices/random constructors cannot occur in native ODE bodies or as ODE
states/parameters. Existing real/Pentarnion native models remain unchanged.
Default bounds: 100,000 entries per dense array, dimensions in 0..100,000,
1,000,000 unique retained real coordinates across matrix variables, with five
coordinates counted per Pentarnion entry. Aliases count once. Runtime operation,
cancellation, source/AST and finite-result bounds also apply to matrix operations.
display/workspace snapshots print all entries for arrays up to 1,024 entries;
larger arrays show their dimensions and a bounded 6-by-6 preview, retaining every
numerical entry for computation.

L31. ARRAY CONSTRUCTORS AND REPRODUCIBLE RANDOM VALUES
zeros(n), ones(n), eye(n) create n-by-n real matrices. Two arguments specify
rows and columns: zeros(rows,columns), ones(rows,columns), eye(rows,columns).
eye uses ones on the main diagonal and zeros elsewhere, including rectangular
shapes. Dimension expressions have Integer type and may be zero, within L30's
allocation bounds. Constructors with dimensions return arrays even when 1-by-1.

linspace(start,stop[,count]) returns a real row vector, default count=100.
Endpoints are real scalars, count is a nonnegative Integer. count=0 returns a
1-by-0 array; count=1 returns stop. Both endpoints are included when count>=2.
Use linspace for evenly spaced vectors; a:b range expansion is not introduced.

rand() returns one uniform real sample in [0,1); randn() returns one standard
normal real sample. rand(n)/randn(n) create n-by-n arrays; rand(rows,columns)
and randn(rows,columns) use the specified shape. randi(imax) returns an Integer
uniformly in 1..imax; randi(imax,n) and randi(imax,rows,columns) return real arrays
whose entries are integer-valued. imax is an Integer in 1..2^53-1.

rng(seed); resets the Studio stream to a nonnegative signed 64-bit Integer seed.
rng("default"); resets the default seed, 5489. These are Void calls, not values.
The stream uses mt19937_64, a 53-bit uniform conversion, Box-Muller normal samples
and unbiased bounded integer sampling. The same seed and sequence of Studio
calls reproduce the same stream within the same build/platform. Normal samples
may differ in their last bits across math libraries. This is not a promise of
MATLAB-identical random values. A session shares its stream across console commands and script runs;
clear/clc do not reset it. Reset Workspace restores the default stream. Checking
does not draw samples, and cancellation restores the pre-request RNG state.

size(A) returns the real row vector [rows,columns]. size(A,dimension) returns an
Integer; dimensions above 2 return 1. numel(A) returns the total entry count.
length(A) returns the largest dimension, or 0 for an empty array. Numeric scalars
are treated as 1-by-1 by these size queries. No higher-dimensional arrays exist.

New declaration/function names are protected in language 0.2. Existing 0.1 files
may retain variables with these names; they are not silently reinterpreted.

L32. COPY SOURCE WITH SYNTAX FORMATTING
This editor feature adds no .p syntax and never checks or executes source.
Normal Copy/Ctrl+C and Cut/Ctrl+X provide both Qt's original plain-text selection
and a portable HTML representation. Rich-text destinations such as Word and
browser editors can retain the source colors; plain-text destinations still
receive the same ordinary text. Destination paste preferences can discard style.

HTML uses a preformatted monospace block and escaped colored spans derived from
the source editor's current QTextLayout highlighter ranges. Foreground colors,
font weights and italics are retained, with normal editor colors for unstyled
identifiers and spaces. It preserves selected Unicode, tabs, spaces, blank lines
and partial tokens across blocks. HTML metacharacters are escaped as source
text, never executable markup. Line-number gutters, cursor/selection backgrounds
and diagnostics are not copied into the code fragment.

The normal Qt clipboard MIME adapter supplies platform rich-text formats,
including Windows CF_HTML; no Word dependency or external clipboard tool is used.
Only the selected source is copied. Copy leaves the buffer, revision, undo stack,
encoding/newline metadata and safe-save behavior unchanged. Cut retains standard
Qt removal/undo behavior and adds the same rich clipboard data.

To bound memory, selections above 4,194,304 UTF-16 characters or HTML output above
8 MiB fall back to ordinary plain text. The plain-text selection is not truncated.
Copy may refresh lexical highlighting before reading ranges; it never runs the
static checker, interpreter, native compiler or an ODE solve.
