Windows compiler: existing C:/msys64/ucrt64/bin/g++.exe (GCC 16.2.0).

WINDOWS — CMAKE OR CODE::BLOCKS
  powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1 -Configuration Debug -Test
  powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1 -Configuration Release -Test
  powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1 -Headless -Test
Or, from the repository root:
  third-party/windows-deps/ucrt64/bin/cmake.exe --preset windows-debug
  third-party/windows-deps/ucrt64/bin/cmake.exe --build --preset windows-debug
  third-party/windows-deps/ucrt64/bin/ctest.exe --preset windows-debug
CMake automatically deploys required developer DLLs and Windows Qt platform
plugins beside the output executables. No installed Qt directory is required
on PATH to launch a completed developer build from its bin directory.

Open Pentarnion-Windows.cbp in Code::Blocks. Select Debug or Release and use
Build/Run. Custom make commands invoke tools/build.ps1; CMake/Ninja owns the
source/dependency graph, including AUTOMOC. Per-file compile builds the graph.
For interactive debugging select an appropriate GNU GDB debugger and point it
to third-party/windows-deps/ucrt64/bin/gdb.exe. This revision does not change
the user's global Code::Blocks compiler/debugger settings automatically.
The scripts explicitly select the existing UCRT64 compiler regardless of the
Code::Blocks editor's default compiler profile. PENTA_MSYS2_ROOT overrides
the existing compiler root when using the wrapper on another machine.

CI definitions for Windows and Linux are included but have not been dispatched
or published by this local task. GUI tests use the offscreen platform; a real
desktop launch still needs to be checked on each supported OS.

ORIGINAL DESIGN NOTES (retained for context)

Proposed: Windows 11, Code::Blocks, MSYS2 UCRT64 GCC, C++20 (no modules),
CMake, Ninja, Qt 6 Core/Gui/Widgets/Test, Eigen for rank-revealing 5x5 solves.
Do not introduce Qt plotting, WebEngine, SUNDIALS, LLVM or Python runtime deps.

1. INSPECT ONLY FIRST
In an MSYS2 UCRT64 shell:
  echo "$MSYSTEM"
  which g++ cmake ninja
  g++ --version
  cmake --version
  ninja --version
  pacman -Q mingw-w64-ucrt-x86_64-qt6-base
  pacman -Q mingw-w64-ucrt-x86_64-eigen3
Record missing packages and versions. Do not automatically update the whole
MSYS2 installation or mix its /usr compiler with /ucrt64 native libraries.
Package availability/names must be checked locally before installation.

2. ONE BUILD AUTHORITY
Use CMake+Ninja; create Windows UCRT64 Debug/Release CMake presets and a
separate optional headless-core build. When the repository has CMake files:
  cmake -S . -B build/debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
  cmake --build build/debug
  ctest --test-dir build/debug --output-on-failure
These build the IDE and its tests. They do NOT compile .p source files.

3. CODE::BLOCKS
Use Code::Blocks to edit/debug and invoke the CMake build as an external tool
or documented custom build command. The included .cbp files implement that
route on both platforms. All Windows dependencies use the same UCRT64
compiler/runtime. Do not maintain a second independent source/dependency list
in a .cbp file. A thin navigation/debug wrapper may be added only if needed.
CMake's CodeBlocks extra generators are deprecated since 3.27; do not make
them the project's required long-term build route. Inspect local capabilities
rather than assuming any particular generator has been removed.

4. DEPENDENCY DISCIPLINE
Use find_package and imported CMake targets. Pin actual installed versions in
the eventual reproducibility note. Do not download random headers inside a
build or fetch unpinned dependencies without permission. Check applicable
Qt/Eigen redistribution requirements before distributing binaries; this
specification does not provide a licence clearance opinion.

5. C++ RULES
RAII, explicit ownership, no mutable global algebra, no fast-math by default,
no raw Windows-only calls inside penta_algebra/penta_language. Use filesystem
paths through adapters, not narrow-string assumptions. Enable useful warnings
without initially treating third-party headers' warnings as project errors.
Use QtTest/CTest; allow the base algebra target to be built without the GUI.

6. LOCAL ACCEPTANCE
Record successful builds/tests AND a manual Windows launch. A Linux/container
build cannot establish Windows GUI behaviour. Test a project path containing
spaces and non-ASCII characters. Verify the runtime DLL search path without
copying DLLs from incompatible compiler distributions.

Official sources are recorded in references/sources.txt.
