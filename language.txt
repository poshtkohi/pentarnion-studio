PENTARNION LANGUAGE 0.2 — NORMATIVE LANGUAGE SPECIFICATION
Status: checked interpreter, cached native scalar/ODE kernels and lazy numerical module.
Explicit Run File/Command Window executes source. Scientific foundations: L39-L46.
File extension: .p. Encoding: UTF-8. Case-sensitive identifiers.
This document defines implemented syntax, arithmetic semantics and execution
contracts. Deferred capabilities are explicitly identified.

L01. PROGRAM STRUCTURE
One file is one independent top-level scope. Each executable-looking
statement ends with ';', except braced ode/function/control definitions.
A line break is whitespace, not a statement end; inside a matrix literal it can
separate rows (L30).
Empty statements are permitted. Multiple statements per line are permitted.
Forward references and implicit variable declarations are not permitted.
Language 0.2 supports conditions, loops and typed functions (L35), callbacks,
records, source imports and a restricted native scalar subset (L39-L42).
Dedicated ode blocks define pure native ODE models (L23-L26). Execution is explicit.

Examples:
  real m = 1.0;
  integer count = 10;
  pentarnion p = 1 + i - j + ell;
  p = p + 2;
  p * i;       % Evaluated and discarded in a script; use display(p*i) for output.

L02. LEXICAL RULES
ASCII identifiers: [A-Za-z_][A-Za-z0-9_]*. Unicode is allowed in comments,
strings and filesystem names, but not identifiers in versions 0.1/0.2.
Integer literals: decimal digits, no base prefixes or digit separators.
Real literals: decimal point and/or exponent, e.g. 1.0, .5, 1., 2e-3.
Leading +/- are operators, not part of the number token.
An integer literal must fit signed 64-bit, including the special directly
negated minimum value -9223372036854775808. No wraparound or modulo parsing.
A real literal must be representable as a finite binary64 value.
No implicit multiplication: 2i is an error; write 2*i.
% begins a line comment. %{ and %} on otherwise-whitespace lines delimit a
non-nesting block comment. Inside a block comment all characters are comment
text until a closing-delimiter line. Delimiters in strings have no effect.
Double-quoted strings support \\, \", \n, \r, \t only. In v0.1 strings occur
in use_algebra, display, quoted clear targets and plotting metadata; there is no declared string type.
In profile 0.2, single quote denotes a time derivative on the left side of an
ODE equation (L23), or postfix conjugate transpose in an expression (L30).
The two-character operator .' is plain transpose. No single-quoted strings exist.

L03. RESERVED NAMES
Keywords: integer, real, pentarnion, range, use_algebra; profile 0.2 adds ode,
solution, matrix, vector, realmatrix, pentarnionmatrix, logicalmatrix, string,
void, if, else, for, while, break, continue, return, function, true, false, end,
callback, options, record, tuple, complex, import, as and native.
algebra and element are contextual type words (L100); existing identifiers and
functions named algebra/element remain usable outside the declaration syntax.
Read-only basis names: i, j, k, ell.
Built-in function names (including display in 0.2) are protected from redeclaration.
No numerical constant named e is introduced. '1' is the integer literal,
embedded as the algebra identity when a Pentarnion is required.
Future constructs such as search/simulate are unsupported and must not be
styled or accepted as implemented keywords. New 0.2 names retain their previous
identifier meaning when checking existing language 0.1 documents.

L04. ALGEBRA CONTEXT
Optional first nonempty/noncomment statement:
  use_algebra("A_gamma", gamma=1);
Exactly one is allowed. gamma is a signed numeric literal in [0,1], not a
variable or time-dependent expression. Only the stated algebra alias is
accepted in v0.1; it resolves to versioned ID A_gamma_v1.
Without a directive, use the project's algebra/gamma. Without a project,
use A_gamma_v1, gamma=1. A file directive explicitly overrides the project
default for that file only. The effective context appears in the status bar.
Context is immutable during a document analysis. No variable from another
file enters the scope. All legacy Pentarnion elements in one file use this
context; L100's explicitly typed native algebra definitions may coexist.

L05. DECLARATIONS AND ASSIGNMENT
  integer n = 10;
  real x = 0.25;
  pentarnion p = pent([1, 0, -1, 0, 1]);
Declarations require initialisers. Reassignment preserves the declared type.
Duplicate declarations, use before declaration and basis-name assignment
are errors. There are no implicit 'ans' values or dynamically changing types.

Value types:
 integer: signed 64-bit integer.
 real: IEEE-754 binary64 approximation.
 pentarnion: five real coefficients tied to an immutable algebra context.
 integer range, real range: separate finite-range descriptor types.
 realmatrix, pentarnionmatrix: dense array types, distinct from scalar values.
 logicalmatrix: dense logical array, distinct from numeric index vectors.
 complex: explicit two-real scalar, distinct from Pentarnion basis i.
 string, callback, tuple and immutable options/record: see L35 and L39-L42.

Implicit widening: integer -> real; integer/real -> scalar Pentarnion.
Integer/real values also embed into Complex. No implicit real -> integer,
Pentarnion -> real/integer, or Complex/Pentarnion mixing.
Known integer-to-real loss of exactness may produce a warning; unknown
values cannot be certified lossless by the editor.
A pentarnion variable may have zero scalar part, but is never forced pure.

L06. CONSTRUCTORS AND BASIC EXPRESSIONS
  pent([e0, e1, e2, e3, e4])
Exactly five scalar expressions; basis order is (1,i,j,k,ell). Values are
widened to real coefficients. This scalar constructor remains distinct from
the dense matrix/vector array literals added by L30-L31.
Equivalent mathematical representations include:
  pentarnion p = 1 - j + ell;
  pentarnion q = pent([1, 0, -1, 0, 1]);

L07. OPERATORS AND TYPES
+, - : integer/integer -> integer; mixed scalar -> real;
       at least one Pentarnion -> Pentarnion by scalar embedding.
unary +/-: preserves type for the three scalar/element types.
* : integer/integer -> integer; mixed scalar -> real;
    scalar/element -> real scaling; element/element -> ordered full product.
/ : scalar/scalar -> real (never truncating integer division);
    element/scalar -> coefficient scaling by the scalar reciprocal;
    scalar/element or element/element -> right division after embedding.
\ : scalar/scalar means RHS/LHS as real;
    scalar\element -> scaling the element by inverse scalar;
    element\scalar or element\element -> left division after embedding.
^ : scalar base and scalar exponent -> real; runtime rejects
    out-of-real-domain cases. Pentarnion base requires an integer exponent,
    returning a Pentarnion. Negative integer exponents use canonical inverse.
No range participates implicitly in arithmetic; using one as a scalar is
an error. No comparisons, boolean type or elementwise operators in v0.1.

L08. NONASSOCIATIVE GROUPING
Multiplication/division parse left to right, but an unparenthesised
multiplicative chain containing >=3 Pentarnion-valued operands is rejected.
A grouped subexpression counts as one operand at the enclosing chain.
Scalar operands do not count toward this Pentarnion count.
Examples:
  (B*q)*q             valid
  B*(q*q)             valid and distinct
  a*(B*(q*q))         valid
  a*B*q               valid if a is scalar: two element operands
  B*q*q               E1301: require explicit grouping
  p/q*r               E1301: require explicit grouping
Keep Group nodes/source spans in the AST. Never flatten, commute, reassociate,
cancel inverses, or use norm composition without a documented valid identity.
Powers of one element are unambiguous for A_gamma_v1 (power associativity).
This does NOT authorize replacing (B*q)*q by B*(q*q).

L09. PRECEDENCE
High to low: primary/group/call with postfix indexing/transpose; exponentiation
(^ and .^); unary sign; * / \ .* ./; + -.
Exponentiation is right-associative. Unary sign binds below exponentiation,
while a signed exponent is allowed: -q^2 means -(q^2); q^-1 means q^(-1).
A Pentarnion exponent must type-check as integer; scalar ^ returns real.
Thus q^(2^3) is a type error in v0.1, while q^8 is valid. No hidden real-to-
integer coercion is introduced to make that case work.

L10. CANONICAL RECIPROCAL AND EQUATION DIVISION
For nonzero Pentarnion q:
  inv(q) = q^(-1) = conj(q)/norm2(q).
This is the canonical reciprocal in the one-element subalgebra.
  p/q   means the unique x with x*q = p.
  p\q   means the unique x with p*x = q.
In general p/q is NOT p*inv(q), and p\q is NOT inv(p)*q.
With a real nonzero denominator these coincide with real coefficient scaling.
Division by zero, singular nonunique solves, inconsistent equations and
unacceptable ill-conditioning are runtime/core errors, not automatic
least-squares results. Static validation normally cannot decide solvability.
The C++ library must expose richer solve status and numerical residuals.
Do not claim q*inv(q)=1 supplies cancellation across arbitrary third factors.

L11. BUILT-IN SIGNATURES
sqrt(integer|real) -> real; real nonnegative domain (runtime condition).

sin/cos/exp/sinh/cosh(integer|real) -> real.
sin/cos/exp/sinh/cosh(pentarnion) -> pentarnion using L18 one-element calculus.
tan/asin/acos/atan/tanh/asinh/acosh/atanh/log/log10/log2/abs/floor/ceil/round(integer|real) -> real.
atan2(integer|real, integer|real) -> real, argument order atan2(y,x).
These additional functions are protected names in profile0.2. They do not have
Pentarnion overloads except for the five explicitly listed above. No componentwise
extension is implied. Existing sqrt remains real-only.

pent([scalar,scalar,scalar,scalar,scalar]) -> pentarnion.
conj(pentarnion) -> pentarnion.
scalar(pentarnion) -> real.
pure(pentarnion) -> pentarnion with coefficient 0 equal to zero.
norm2(pentarnion) -> real, N(q)=sum(q_r^2), not its square root.
inv(pentarnion) -> pentarnion; nonzero domain (runtime condition).
coeff(pentarnion,integer) -> real; zero-based index in 0..4.
commutator(pentarnion,pentarnion) -> pentarnion, p*q-q*p.
associator(pentarnion,pentarnion,pentarnion) -> pentarnion,
  (p*q)*r-p*(q*r).
display(expr[,expr...]); prints one or more scalar, Pentarnion, range-descriptor
 or string-literal arguments, separated by spaces, followed by a newline.
Display is a top-level statement, not a value-returning expression.
clc; clears the visible/output transcript, preserving variables/context/history.
clear; and clear all; remove all user variables, preserving algebra context.
clear p q; removes named variables; unknown names are a no-op. Protected bases
and names cannot be cleared. A cleared variable may be redeclared with a new type.
The names disp/print/solveODE/search remain unsupported. plot(xSeries,ySeries)
is a profile0.2 curve statement; odesolve is spelled in lowercase (L23-L26).
Explicit plot2/plot3 and figure commands are defined in L17.
The checker validates without evaluating. Explicit Run invokes these operations.

L12. FINITE RANGE DECLARATIONS
  integer range orders = 1:1:5;
  real range strengths = 0.05:0.05:0.50;
The three-part form start:step:stop is required in v0.1. All components are
scalar expressions; integer range requires integer components. real range
allows integer-to-real widening. Optional ordinary reassignment must use a
range descriptor of the same type, never a scalar.
  orders = 2:2:10;
  integer range copy = orders;
Zero literal step is a static error. Computed steps are checked at runtime;
static checking never evaluates them. Direction inconsistent
with the endpoints denotes an empty finite range (not an infinite loop).
If start==stop and step!=0, the range contains that one value.
Ranges are not continuous intervals and do not imply sampling/optimisation.
The interpreter computes and validates range fields but never materialises/enumerates them.

Future enumeration contract, recorded to avoid ambiguity:
 integer: use checked integer arithmetic; include x=start+k*step while it is
 inside the closed interval in the step direction. Stop before overflow.
 real: use specified binary64 non-fused multiply then add for each k (not
 repeated accumulation); include only generated points satisfying x<=stop
 for positive step, x>=stop for negative step. Do not force a nominal
 endpoint or silently apply an epsilon. Log actual values when execution is
 introduced. Enforce a finite count budget and error on non-progress/overflow.

L13. EBNF (COMMENTS REMOVED; MATRIX SEPARATORS USE ORIGINAL SOURCE GAPS)
program       = {";"}, [directive], {statement}, EOF ;
directive     = "use_algebra", "(", string, ",", "gamma", "=",
                signed_number, ")", ";" ;
statement     = timer_stmt | ode_def | subplot_stmt | xy_plot_stmt | declaration | indexed_assignment | assignment | display_stmt | clear_stmt | clc_stmt | plot_stmt | figure_stmt | clf_stmt | close_stmt | dock_stmt | tile_stmt | figure_text_stmt | expression, ";" | ";" ;
display_stmt  = "display", "(", display_arg, {",",display_arg}, ")", ";" ;
display_arg   = expression | string ;
clear_stmt    = "clear", [clear_names | "(",[clear_args],")"], ";" ;
clear_names   = identifier,{identifier} ;
clear_args    = string,{",",string} ;
clc_stmt      = "clc", ["(",")"], ";" ;
plot_stmt     = ("plot2"|"plot3"), "(", axis, ",", axis, [",",axis], ",", expression, {",",expression}, ")", ";" ;
axis          = string ; (* literal distinct axis names; exactly 2 for plot2, 3 for plot3 *)
figure_stmt   = "figure", "(", [figure_args], ")", ";" ;
figure_args   = expression, [",",figure_properties] | figure_properties ;
figure_properties = string, ",", string, {",",string,",",string} ;
dock_stmt     = ("dock"|"undock"), "(", expression, ")", ";" ;
tile_stmt     = "tilefigures", "(", [string,[",",expression,",",expression]], ")", ";" ;
figure_text_stmt = ("title"|"xlabel"|"ylabel"|"zlabel"|"caption"), "(", string, [",",string,",",string], ")", ";" ;
clf_stmt      = "clf", ["(",")"], ";" ;
close_stmt    = "close", "(", (expression|string), ")", ";" ;
declaration   = ("integer"|"real"), ["range"], identifier, "=",
                initializer, ";"
              | ("pentarnion"|"solution"|"matrix"|"vector"|"realmatrix"|"pentarnionmatrix"), identifier, "=", expression, ";" ;
assignment    = identifier, "=", initializer, ";" ;
indexed_assignment = identifier, "(", expression, [",",expression], ")", "=", expression, ";" ;
initializer   = expression, [":", expression, ":", expression] ;
expression    = product, {("+"|"-"), product} ;
product       = unary, {("*"|"/"|"\\"|".*"|"./"), unary} ;
unary         = ("+"|"-"), unary | power ;
power         = primary, [("^"|".^"), unary] ;
primary       = atom,{".",identifier | "(",expression,[",",expression],")" | "'" | ".'"} ;
atom          = number | identifier | basis | group | call | pent_ctor | ode_solve | matrix_literal ;
matrix_literal = "[", [matrix_row,{(";"|matrix_newline),matrix_row}], "]" ;
matrix_row    = expression,{(","|matrix_space),expression} ;
(* matrix_space/newline are source gaps between tokens; signed-entry ambiguity
   follows L30. Scalar entries only; no nested array concatenation. *)
group         = "(", expression, ")" ;
call          = builtin_name, "(", [call_arg,{",",call_arg}], ")" ;
call_arg      = expression | string ; (* strings only for explicitly allowed options *)
pent_ctor     = "pent", "(", "[", expression, {",",expression}, "]", ")" ;
signed_number = ["+"|"-"], number ;
Type checking, rather than grammar alone, enforces constructor length,
range/scalar assignment, protected names, power types and association rules.
In the EBNF the escaped display "\\" denotes one backslash token.

L14. STATIC ANALYSIS DOES NOT EXECUTE
Diagnose literal overflow, a literal zero divisor, wrong arity/types, missing
semicolons, unknown names, illegal range use and unsafe unparenthesised chains.
Do not evaluate p, q, a function call or an assignment to discover its value.
Limited signed-literal recognition is allowed; it is not a general constant
folder. Computation-dependent errors remain documented potential runtime
conditions. 'Syntax valid' is never an assertion of numerical invertibility.

L15. OUT-OF-SCOPE SYNTAX
No loops, conditionals, general user functions, imports, namespaces, higher-dimensional arrays,
surface/mesh calls, research-search commands, shell commands, arbitrary source file I/O,
comparison operators, mutable gamma, compiler directives or auto-execution.
Unsupported constructs produce a precise unsupported-feature diagnostic.

L16. INTERPRETER AND COMMAND WINDOW PROFILE0.2
New projects/standalone source default to0.2. Projects marked0.1 remain editable
and checkable; explicitly upgrade their metadata to execute scripts. display,
clear and clc are protected builtins only in0.2, preserving old0.1 identifiers.
The checker parses/types the entire source without evaluation before execution.
Explicit Run File starts a fresh independent scope, then retains its completed
variables for console inspection. Direct console commands share typed bindings.
Static errors preserve the workspace; runtime errors stop with earlier completed
statements/output retained. Cancellation rolls back the request's workspace.
No command runs automatically when opening/saving/typing/checking source.

In the Command Window only, the final semicolon is optional. Without it, the
last expression/assignment/declaration value echoes; with it, no automatic echo.
display always prints. Scripts still require semicolons. clc clears output and
keeps command history/variables; clear keeps algebra context. Changing gamma with
existing variables is rejected until clear in an earlier command. Reset Workspace
is a separate UI action that also restores current project context defaults.

Console-only run("path.p") opens/focuses and executes that .p buffer. Relative
paths use project root, active-source directory or current directory in that
order; absolute paths are accepted. This complete console command invokes no
shell command and is not a script import. Native ODE compilation is restricted
to the checked compiler backend in L23-L24. Project-tree right-click Run
and Run File use the same execution path. External penta-run executes files too.

Integer arithmetic is checked signed64; real arithmetic is finite binary64.
Powers and sqrt enforce real-domain rules. Division distinguishes strict unique
operator solves from canonical reciprocal multiplication. Display uses locale-
independent15 significant digits and does not erase tiny nonzero coefficients.
Ranges compute fields and reject zero steps but are never enumerated here.

Resource defaults:4MiB source,200000 tokens/nodes,50000 statements,128 AST depth,
128 static diagnostics,1000000 evaluation operations,1MiB output/request and
50000 workspace variables. Long flat chains are depth-bounded too. Console history
holds200 commands; the transcript is bounded8MiB and scrollable. No runtime
filesystem/network/process capability, except explicit GUI/CLI source-file loading
and the bounded native ODE compiler/cache backend in L23-L24. General native .p
compilation, PDEs, parallel work and research search remain future work.

L17. VECTOR FIGURES (ADDITIVE PROFILE0.2 EXTENSION)
plot2("i","j",p[,q...]); selects two distinct displayed coefficients.
plot3("i","j","k",p[,q...]); selects three distinct displayed coefficients.
Axes are literal strings from "1","i","j","k","ell"; "1" means scalar coefficient.
There must be at least one Pentarnion-valued expression after the axes. Scalars,
ranges and strings are not vector arguments; use an explicit pent constructor
when representing a scalar-axis vector. At most256 vectors occur in one call.
Expressions retain ordinary typing, operand order and explicit grouping rules.
No implicit sampling, field/mesh/PDE plotting or backend-specific names. L30 adds
real coordinate vector plots separately from these canonical projections.

figure(); creates/selects the lowest available positive figure number.
figure(n); selects figure n, creating it if absent. n has Integer type,1..64.
plot2/plot3 with no selected figure creates/selects figure1. Every plot call
replaces only the selected figure's active panel. Multiple vector arguments overlay
in one call. Figure commands have Void type and cannot be assigned as handles.
clf; or clf(); clears only the selected figure (no-op when none is selected).
close(n); closes figure n (absent valid numbers are a no-op).
close("all"); closes every plot figure. No other close string is accepted.
clear/clc/Reset Workspace preserve figures. No hold command is supported yet.

Each vector is an arrow from the origin to its selected-coordinate endpoint,
with an arrowhead at that endpoint and equal axis scaling. An exactly zero
projection is shown as a point, even if omitted coefficients are nonzero.
The view labels projection axes/context and retains all five coefficients for
inspection. Display projection never modifies the algebra value or gamma.
Figures start as tabs inside Studio; explicit undock/tiling commands may create
owned figure-only windows (L20). The Command Window remains unified. Export Image
exports the selected figure to PNG, JPEG or SVG through the GUI. Each subplot's
Save icon exports just that panel in the same formats (L29). Source scripts have
no arbitrary filesystem-writing/export function in this revision.

Plot/figure statements always act when executed; semicolons suppress neither
plots nor display. Static checking never creates figures. Ordered figure actions
are emitted only during explicit execution; cancellation discards those actions.
Ordinary runtime failures retain preceding completed figure actions. Resource
limits include256 figure actions per request and64 live figure numbers.
penta-check accepts this syntax without Qt/VTK. penta-run diagnoses that figure
commands require Studio instead of silently ignoring requested plots.

L18. ELEMENTARY FUNCTIONS AND REAL DOMAINS
Authority: the project's original algebra research and public algebra contract.
The implemented one-element slice formulas below preserve that convention.
For p=a+u, r=hypot(u1,u2,u3,u4), the associative one-element slice gives:
 exp(p)  = exp(a)*(cos(r)+(u/r)*sin(r))
 sin(p)  = sin(a)*cosh(r)+(u/r)*cos(a)*sinh(r)
 cos(p)  = cos(a)*cosh(r)-(u/r)*sin(a)*sinh(r)
 sinh(p) = sinh(a)*cos(r)+(u/r)*cosh(a)*sin(r)
 cosh(p) = cosh(a)*cos(r)+(u/r)*sinh(a)*sin(r)
At r=0, use the real scalar result and zero pure coefficients. Pure-direction
ratios use the continuous limits; tiny nonzero components are retained when
representable. These are whole-element functions, never coefficientwise maps.
Context/gamma is preserved. No multielement identities such as exp(p+q)=exp(p)exp(q)
are assumed. Standard floating approximations, checked finite results and their
normal representability limits apply; tests are not a symbolic proof.

Real trig angles are radians. asin/acos require -1<=x<=1; acosh requires x>=1;
atanh requires -1<x<1; sqrt requires x>=0; logarithms require x>0. exp/hyperbolic
overflow and nonfinite results are explicit runtime failures. floor/ceil/round
return Real values; round uses nearest integer with halfway cases away from0.
atan2 uses the host standard math convention, including signed-zero cases.

L19. SOURCE AUTOSAVING AND CONSOLE INTERACTION (EDITOR, NOT SOURCE SYNTAX)
The Command Window is one text document containing protected history/output and
one editable >> input region while ready. During work the prompt/input is hidden
and a protected Running status appears; Stopping appears after cancellation is
requested. The ready prompt returns only after the worker finishes. Transcript
scrolling, selection and context-menu Copy remain available. Enter submits; Shift+Enter inserts a newline;
Up/Down recalls history. clc leaves one fresh prompt, retaining history/variables.
Output, errors and commands occupy that same surface. Problems is optional.
Named modified sources autosave after the mouse leaves the source viewport,
even when keyboard focus remains inside it, after a short debounce (~500ms).
Focus/tab changes and configurable periodic saving (default60s) also trigger
safe saves. Untitled buffers use owned recovery snapshots until explicitly named.
Autosave uses the same atomic save/external-change protection as manual Save,
does not execute source, and does not open blocking save dialogs on conflicts.

L20. FIGURE WINDOWS, NAMES AND TILING
These are additional Void statements in profile0.2; old0.1 identifier compatibility
is preserved. No assignable graphics-handle/object type is introduced.
figure(1,"Name","Vector addition"); selects/creates1 and changes its display name.
figure("Name","A new figure"); creates/selects the lowest available figure ID.
The optional property pairs Name and NumberTitle may occur in either order.
Property keys and on/off values are case-insensitive; unknown/duplicate properties
are errors. NumberTitle is "on" by default; "off" suppresses the numeric prefix
when a custom name is present. Name is literal plain text, not interpreted math.
figure(1) without properties preserves the existing name/NumberTitle. clf retains
figure identity/name but clears plot contents and annotations.

undock(n); places an existing figure in its own owned figure-only window.
dock(n); returns an existing figure to Studio. n has Integer type in1..64;
the target must already be open. Data, context, labels, colours and camera remain
with the same figure. Closing an undocked window closes that figure, not Studio.
All owned floating windows close when Studio/FigureManager is destroyed.

tilefigures(); or tilefigures("studio"); docks and tiles all open figures in Studio
using an automatic grid. tilefigures("desktop"); undocks and tiles them on the
current available monitor. Optional rows/columns choose a grid:
tilefigures("studio",1,2); or tilefigures("desktop",2,2);
Dimensions have Integer type in1..64; product<=64 and grid capacity must fit all
currently open figures. Capacity/display errors leave the current arrangement
unchanged. No figures is a no-op. Desktop cells must fit the available display.
The UI provides Dock, Undock, Tile in Studio, Tile on Desktop, Tabs, camera reset
and image export. Tile dropdowns offer Automatic, preset grids and Custom rows/
columns with the same capacity/64-cell validation. Explicit unused grid cells keep
their space; Cancel preserves the layout. Floating figures expose the same choices.
Tabs returns docked figures to tabbed view. Tiling arranges
existing figures; it does not create subplots within one figure.

L21. TITLES, AXIS LABELS, CAPTIONS AND LATEX MATH
title("$p+q$"); xlabel("$i$"); ylabel("$j$"); zlabel("$k$");
caption("$p+q=2+2j$");
These affect the selected figure (create/select figure1 when none is active).
The optional pair "Interpreter","latex" or "Interpreter","none" selects math
rendering or literal text. Default is latex, supporting mixed plain text and
$...$ mathematical spans. Empty text clears the corresponding annotation.
Plot replacement preserves annotation overrides; clf clears them. Axis projection
metadata remains available separately, so a custom label never changes which
coefficient is plotted. Labels/captions appear in the actual image export.

The renderer supports a documented mathematical subset through native
JKQTMathText, including Greek symbols, sub/superscripts, fractions, roots, sums,
integrals, standard operators and selected matrix environments. It is not a TeX
document engine: file/package/macro execution and numeric font/dimension controls
are unavailable. Unsupported/malformed math produces a clear figure error and
retains the previous valid annotation. No TeX/Python executable is launched.
Font resources are bundled XITS. A literal source string must escape a backslash:
title("$p\\star q$"); caption("$(p\\star q)_k=2\\sqrt{2}$");
After source decoding, the renderer receives ordinary LaTeX backslashes.
Each text literal is limited to4096UTF8bytes; native labels enforce64group levels,
bounded command/script complexity and a maximum2048x1024-pixel label image.
Rendered labels are positioned inside the VTK view and survive resizing,
rotation, docking/undocking, tiling and PNG/JPEG/SVG export.

L22. SAVE BEFORE SCRIPT RUN
Run File/F5, project-tree Run and console run("file.p") use one save-before-run
path. A modified named script is safely saved before the execution snapshot.
An unnamed script opens normal Save As first. Cancellation or any save failure,
external disk conflict/unavailability, or changed project metadata stops the run
before worker submission; no script statements or plot actions execute.
Execution captures the saved source/profile only after successful persistence.
Checking still uses unsaved buffer snapshots without mandatory saving, and never
executes source. Independent autosave remains governed by L19. Interactive direct
commands do not require a source-file save.


L23. NATIVE ODE MODELS AND SOLUTIONS (ADDITIVE PROFILE0.2 EXTENSION)
ode flow(t, pentarnion p; real a, pentarnion b) {
    p' = b*p-a*p;
}
solution s = odesolve(flow, p=p0, a=damping, b=B,
    t0=0,t1=20,sample_step=0.01,method="bdf",
    jacobian="analytic",rtol=1e-8,atol=1e-10);

Time is the first untyped identifier and has real type inside the block. Each
state before ';' and parameter after ';' has an explicit real/pentarnion type.
The parameter section may be omitted or empty. There must be at least one state.
Every state has exactly one derivative assignment; equation order is immaterial.
No local declarations, loops, branches, calls to user code, nested solves or side
effects occur in an ODE body. No workspace values are implicitly captured: only
time, declared states/parameters and read-only basis names are visible. Local
names are unique and cannot collide with protected names. State/parameter names
also cannot collide with solver option names.
A state named t is disallowed because s.t is reserved for sampled output times.
ODE model names cannot be reassigned. A solution variable may receive a later
solution, with its checked named-state schema updated to match.

odesolve names an earlier ODE model, then explicitly supplies every state initial
value, parameter value and t0/t1 using unique named arguments. Type widening is
integer->real->scalar Pentarnion; no implicit narrowing. All supplied values are
evaluated once before integration and remain fixed throughout that solve. Time
arguments may appear within the RHS. The immutable A_gamma_v1 context applies.

Options: t0,t1 required finite reals with t1>=t0; equality returns the initial
state only. sample_step positive (default.01);
method is a literal "bdf" (default), "adams", "erk" or "esdirk";
jacobian is a literal "analytic" (default) or "finite_difference";
rtol in (0,1), default 1e-7; atol>0, default 1e-9. Absolute tolerance is a scalar
applied to every real coordinate. All methods use native SUNDIALS integration:
  "bdf": CVODE backward differentiation, variable order 1-5, for stiff systems.
  "adams": CVODE Adams-Moulton, variable order 1-12, for nonstiff systems.
  "erk": ARKODE Dormand-Prince 5(4), seven-stage explicit Runge-Kutta.
  "esdirk": ARKODE ESDIRK4(3)6L[2]SA, six-stage implicit Runge-Kutta.
The embedded pairs use adaptive step sizes; the principal solution orders are
5 for erk and 4 for esdirk. Explicit erk is intended for nonstiff systems;
esdirk is intended for stiff systems. There is no automatic method switching.
Solver settings never select an interpreted model fallback.
sample_step controls returned samples, not adaptive internal timesteps. Include
t0 and the exact final endpoint t1 even when the interval is not a multiple of
sample_step. Reject spacing that cannot produce distinct finite binary64 times.

Optional resource limits: max_steps positive integer<=100000000 (default1000000),
max_samples positive integer<=1000000 (default1000000), max_seconds in (0,3600]
(default60, integration only). All failures stop the request with a diagnostic;
no partial trajectory is published as a complete solution. Stop cancellation
terminates compilation/integration and preserves the pre-request workspace.

Supported RHS subset: ordered +,-,*, unary signs, explicit groups; division by
real scalar only; ^ with a literal integer exponent0..64; pent constructors;
conj,scalar,pure,norm2,coeff with literal index0..4; commutator,associator; real
sin,cos,tan,exp,log,sqrt,sinh,cosh,tanh. Reject unsupported calls/operations before
compilation. Whole-Pentarnion elementary functions and equation division retain
their ordinary interpreter meanings outside ODEs but are not native RHS features
yet. Domain failures and nonsmooth/undefined derivatives are errors, not guessed
Jacobians. Gamma stays in [0,1]. Preserve all multiplication order and Group nodes.

Limits:64 real state coordinates,128 real parameter coordinates,20000 RHS nodes.
One real state occupies1 coordinate, one Pentarnion5. Bound each solution to8m
sampled state coordinates. Bound unique retained solution data across the command
workspace to8m state coordinates, counting aliases once; at most64 solves/request.
Project schema_version remains1. Checking, opening, editing and saving do not
compile or run equations. Only explicit execution invokes the native backend.

L24. COMPILER-EMITTED JACOBIANS AND STRUCTURAL NATIVE CACHE
The compiler always generates native RHS and full real-coordinate Jacobian
entry points. Analytic mode uses forward automatic differentiation of the same
grouping-preserving real coordinate computation, with no finite differences.
For n Pentarnion states, the Jacobian has5n rows/columns (plus any real states).
No user-written Jacobian is accepted or required. This is the state Jacobian
df/dy; automatic parameter sensitivity trajectories are a future feature.
For bdf/adams/esdirk, finite_difference mode requests the selected SUNDIALS
integrator's dense difference-quotient Jacobian. The explicit erk method accepts
either jacobian option for source compatibility, but does not evaluate a Jacobian;
its solution summary reports jacobian=not_used. The compiler still emits the same
RHS/Jacobian entry points. Changing method or Jacobian mode does not recompile the
generated native model.

Compile standalone C++20 model code into DLL on Windows/shared library on Linux.
Use the configured CMake compiler directly with argument lists and cancellation/
timeout handling, never a user-provided shell command. Both model functions have
a narrow C ABI; Qt/Eigen/SUNDIALS do not cross the generated-model interface.
Store generated source, atomic manifest and compiled artifact in an ignored
.penta-cache/odes directory beside the project manifest, or beside a standalone
source. The bare projectless console uses application-local storage. No project
manifest rewrite is required, and cache entries are platform/toolchain specific.

Fingerprint the typed ordered model, state/parameter layout, generated support
code, algebra/backend identity, configured compiler identity and target ABI.
Exclude source spans/comments/whitespace, external parameter values, initial
values, gamma values and integrator/output settings. Changing an embedded literal
or equation structure generates a new kernel. Source/binary hashes and ABI are
checked on reuse; incomplete/corrupted artifacts are regenerated under a
cross-process lock. Never reuse a stale incompatible artifact on compiler error.
display(s) reports sample/coordinate counts, cache hit/miss/key, Jacobian mode and
step count. First execution compiles; later executions reuse valid binaries.

L30. REAL AND PENTARNION MATRICES AND VECTORS
This additive language 0.2 extension provides dense two-dimensional arrays.
Scalars and arrays remain distinct types, even for a 1-by-1 matrix. A Pentarnion
scalar is still one algebra element with five coefficients; a vector declaration
below means a row or column array of real or Pentarnion elements.

matrix A = [1,2;3,4];          % infer realmatrix from scalar entries
vector v = [1;2];             % row/column shape checked at runtime
matrix y = A*v;               % matrix by column vector
matrix P = [i,j;k,ell];       % infer pentarnionmatrix
realmatrix R = zeros(2,3);    % explicit real element type
pentarnionmatrix Q = [1,i];   % real entries embed into Pentarnion scalars

matrix/vector declarations infer the array element type from the initializer.
realmatrix and pentarnionmatrix are explicit aliases. Assignment preserves that
declared element type; real arrays may widen when assigned to a Pentarnion array. A scalar
initializer cannot silently become a 1-by-1 matrix; write [value] explicitly.
vector validates row/column orientation when declared; it uses the same matrix
value type and operations thereafter. A vector-valued result of * remains an
array, including a 1-by-1 result from a row-vector/column-vector product.

Literal columns are separated by commas or whitespace, and rows by semicolons
or newlines. All rows must have the same length and entries must be numeric
scalars. L34 extends numeric block concatenation and range expansion. String/object
entries and implicit multiplication remain unsupported. [] is the 0-by-0 real matrix. In a
literal, [1 -2] has two entries; [1 - 2] has one subtraction expression. Group
expressions when spacing could be ambiguous. Existing pent([a,b,c,d,e]) remains
the five-coefficient scalar constructor, not a matrix constructor.

A(row,column) and A(index) use positive Integer indices starting at 1. Linear
indexing is column-major: for A=[1,2;3,4], A(2) is 3. Bounds are checked at runtime.
A(1,2)=value; assigns one compatible scalar element without changing the shape.
Indexed writes preserve aliases as immutable prior values. L34 extends colon/range/vector indexing and end. Logical indexing and array
resizing/deletion remain deferred.

Operators:
  A+B, A-B: equal-size arrays, or a scalar broadcast over every array entry.
  A*B: matrix product when both operands are arrays; columns(A)==rows(B).
       Compatible matrix/vector, row/column and outer products use this same rule.
       If one operand is scalar, * applies it on that same side of each entry.
  A.*B: elementwise ordered products; equal array shapes or one scalar broadcast.
  A./B: elementwise division; divisor entries must be real, with nonzero values.
  A/realScalar: real scaling. Matrix right/left division and equation solves are deferred.
  A.^B: elementwise powers; real scalar/matrix exponents. Pentarnion bases need
        integer exponents (Integer scalar, or checked integer-valued real entries),
        within this array extension's bound -100,000..100,000.
        Matrix ^ is not supported. The existing scalar ^ rule remains unchanged.
  +A, -A: entrywise signs.

Binary matrix products use sum_k A(row,k)*B(k,column), preserving operand order.
No associativity is assumed for Pentarnion matrices. Parenthesize chains with
three or more Pentarnion operands, e.g. (P*Q)*R or P*(Q*R), as for scalar products.
No determinant, matrix inverse, dot/linear solve or spectral operation is added;
inv(p) keeps its existing scalar Pentarnion meaning.

transpose(A) and A.' transpose without conjugation. A' transposes and conjugates
each Pentarnion entry. Real conjugation leaves values unchanged. conj(A),
scalar(A), pure(A), norm2(A) and coeff(P,k) operate entrywise; coefficient k is
still 0..4 and coeff returns a real matrix with the same shape. The five whole
Pentarnion functions sin/cos/exp/sinh/cosh also apply entrywise to arrays. The
remaining one-argument real functions (sqrt, tan, asin, acos, atan, tanh, asinh,
acosh, atanh, log, log10, log2, abs, floor, ceil, round) accept real arrays only.
Their existing domain/finite checks apply to every entry. atan2 arrays are deferred.

plot(x,y) and plot3(x,y,z) accept real row/column vectors or sampled real series.
Coordinate arguments must have equal element counts; full 2D matrices are not
flattened into curves. Existing plot2/plot3 with literal canonical axis names
still projects individual Pentarnion scalars or sampled Pentarnion trajectories.
General matrix-based Pentarnion projection plotting is deferred.

Matrices/random constructors cannot occur in native ODE bodies or as ODE
states/parameters. Existing real/Pentarnion native models remain unchanged.
Default bounds: 100,000 entries per dense array, dimensions in 0..100,000,
1,000,000 unique retained real coordinates across matrix variables, with five
coordinates counted per Pentarnion entry. Aliases count once. Runtime operation,
cancellation, source/AST and finite-result bounds also apply to matrix operations.
display/workspace snapshots print all entries for arrays up to 1,024 entries;
larger arrays show their dimensions and a bounded 6-by-6 preview, retaining every
numerical entry for computation.

L31. ARRAY CONSTRUCTORS AND REPRODUCIBLE RANDOM VALUES
zeros(n), ones(n), eye(n) create n-by-n real matrices. Two arguments specify
rows and columns: zeros(rows,columns), ones(rows,columns), eye(rows,columns).
eye uses ones on the main diagonal and zeros elsewhere, including rectangular
shapes. Dimension expressions have Integer type and may be zero, within L30's
allocation bounds. Constructors with dimensions return arrays even when 1-by-1.

linspace(start,stop[,count]) returns a real row vector, default count=100.
Endpoints are real scalars, count is a nonnegative Integer. count=0 returns a
1-by-0 array; count=1 returns stop. Both endpoints are included when count>=2.
Use linspace or the bounded a:b / a:step:b expansion defined in L34.

rand() returns one uniform real sample in [0,1); randn() returns one standard
normal real sample. rand(n)/randn(n) create n-by-n arrays; rand(rows,columns)
and randn(rows,columns) use the specified shape. randi(imax) returns an Integer
uniformly in 1..imax; randi(imax,n) and randi(imax,rows,columns) return real arrays
whose entries are integer-valued. imax is an Integer in 1..2^53-1.

rng(seed); resets the Studio stream to a nonnegative signed 64-bit Integer seed.
rng("default"); resets the default seed, 5489. These are Void calls, not values.
The stream uses mt19937_64, a 53-bit uniform conversion, Box-Muller normal samples
and unbiased bounded integer sampling. The same seed and sequence of Studio
calls reproduce the same stream within the same build/platform. Normal samples
may differ in their last bits across math libraries. This is not a promise of
MATLAB-identical random values. A session shares its stream across console commands and script runs;
clear/clc do not reset it. Reset Workspace restores the default stream. Checking
does not draw samples, and cancellation restores the pre-request RNG state.

size(A) returns the real row vector [rows,columns]. size(A,dimension) returns an
Integer; dimensions above 2 return 1. numel(A) returns the total entry count.
length(A) returns the largest dimension, or 0 for an empty array. Numeric scalars
are treated as 1-by-1 by these size queries. No higher-dimensional arrays exist.

New declaration/function names are protected in language 0.2. Existing 0.1 files
may retain variables with these names; they are not silently reinterpreted.

L34. INDEXING, SLICES, RANGE EXPANSION AND REDUCTIONS
ARRAY LANGUAGE TOOLS CONTRACT (26 October 2026)

Range values retain their existing integer/real range types. Converting a range
to matrix/vector, using it in array arithmetic or an array-aware call, and using
it in a matrix literal expands it to a real row vector. a:b uses step 1; a:s:b
uses explicit nonzero finite step. Oppositely directed endpoints produce a
1-by-0 vector. Floating endpoints use a bounded roundoff allowance so 0:.1:.3
contains four values. Expansion obeys configured matrix bounds and cancellation;
steps too small to advance binary64 values are rejected.

Matrix literals concatenate scalar, range and numeric matrix blocks. Blocks
within each syntactic row must have equal heights, and expanded rows must have
equal widths. Syntactic rows may contain differing numbers of blocks. Entries
retain order; Pentarnion-valued cells widen the whole array. No implicit scalar
replication occurs during concatenation.

Indices remain one based; one selector uses column-major linear order and two
selectors address rows/columns. A scalar index produces one scalar. Colon, a
range, or a real row/column vector of positive integer-valued indices produces
an array. Repeated and descending indices are supported. Bounds are checked.
Full logical indexing and multidimensional index arrays are not introduced.
end is the current indexed extent: numel(A) for one selector, rows/columns for
two. Nested indexing temporarily replaces and then restores the outer extent.
A(:) always produces a column vector. Other linear selections of vector bases
retain the base row/column orientation; selections of general matrices retain
the index vector's orientation. Empty selectors preserve their resulting shape.

Slice assignment supports one numeric scalar broadcast or a matching array.
Two-selector assignment requires exact selected rows/columns. Linear assignment
allows any RHS vector/matrix shape with matching element count and traverses
RHS entries column-major. The old array is immutable; aliases retain old data.
Repeated targets are assigned in column-major traversal order; the last value
wins. Assignment never resizes/deletes arrays, and real arrays reject Pentarnion
values. Selector expressions are evaluated before the RHS expression.

Real/Pentarnion ODE sampled series support the same read selectors as column
vectors. A small selection need not materialize the entire solution. Selected
results are scalar values or ordinary bounded arrays. Series are immutable.
size/length/numel inspect series without copying the data.

sum(A[,dim]) and mean(A[,dim]) reduce along the first nonsingleton dimension by
default. min/max(A) use the same default; min/max(A,[],dim) specify a dimension.
min/max(A,B) are pairwise operations on equal shapes or one scalar broadcast.
Dimension values must be positive integers; dimensions above two are singleton
dimensions and return the input unchanged. Numeric scalar reductions return a
scalar; array reductions retain their reduced two-dimensional shape.
sum/mean support real and Pentarnion values; min/max require real entries.
sum of an empty extent yields zero; sum([]) is a 1-by-1 zero. min/max over empty
extents retain empty results. mean of an empty extent that would produce numeric
entries is rejected because nonfinite results are not admitted by the language.
Real/Pentarnion ODE series are treated as column arrays by these utilities.
Accumulation uses independent long-double coefficient sums and checks finite
results; no Pentarnion multiplication is reassociated.

Retained scope: existing elementwise .*, ./, .^ and scalar expansion, constructors,
transpose/conjugate transpose, seeded random generation and bounded storage are
preserved. No determinant, matrix inverse/solve, array resizing, higher-dimensional
array, native array ODE state, parallel execution, or PDE feature is introduced.

L35. CONTROL FLOW, FUNCTIONS, VALIDATION AND HELP
CORE LANGUAGE ADDITIONS

Braces delimit control blocks, following the existing ODE body convention:
  integer total=0;
  for(n=1:5){total=total+n;}
  while(total<20){total=total+1;if(total==18){break;}}
  if(total==18){display("done");}else{display("other");}
  if(...) {...} else if(...) {...} else {...} is supported.

for(iterator=values) accepts a finite integer/real range or a real row/column
vector. Integer-range iterators have Integer type; other iterator values are
Real. The iterator is local to the loop; any existing same-named variable is
restored afterwards. break exits the nearest loop; continue starts its next
iteration. while rechecks its real scalar condition each time. Declarations in
if/for/while blocks are local to that block; assignment to existing outer
variables persists. Clear is reserved for top-level workspace management.

Comparison operators: ==, !=, ~=, <, <=, >, >=. Results are Integer 0/1.
true/false are Integer constants. ! and ~ perform logical not; && and ||
short-circuit and accept real scalar conditions. Ordered comparisons require
real scalars. Pentarnion equality compares the five coefficients exactly;
matrix equality compares shape and every coefficient, yielding one scalar.
String equality is supported. No ordering or truth conversion for Pentarnions
or arrays is assumed. Use real predicates such as norm2(p)<tolerance.

function real square(real x){return x*x;}
function integer factorial(integer n){
  if(n<=1){return 1;}return n*factorial(n-1);
}
Function results/parameters may be integer, real, pentarnion, string,
matrix/realmatrix or pentarnionmatrix; void is a result type only. matrix
parameters/results have real entries; use pentarnionmatrix explicitly for
Pentarnion arrays. Define functions before calling them; self-recursion is
supported. Each call has its own parameter/local variable scope and can call
earlier declared functions. There are no implicit global captures. return
matches the declared result type; reaching the end of a non-void function is
a runtime error. void functions use return; or reach the end. Nested function
definitions are rejected. Functions persist between console submissions and
are removed by clear like other workspace bindings.

string name="Susanne"; declares an immutable value with ordinary typed
assignment support. Strings can be compared for equality and passed to
display, user functions, diagnostics and data IO. String concatenation and
arrays of strings are not introduced.

assert(condition[,"message"]); errors on a false real scalar condition.
error("message"); stops execution. warning("message"); writes a warning to
the unified Command Window and continues. help; / help(); provides an
overview; help("topic"); provides builtin/control syntax or a user-function
signature. Unknown help topics report their absence without failing a run.
