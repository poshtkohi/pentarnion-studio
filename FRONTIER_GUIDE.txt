LIVE FITTING/OPTIMIZATION
Open examples/iteration-callbacks/project.pprj. A typical monitor is:
function integer monitor(matrix x,record optimValues=iterationinfo(),string state="iter") {
    if(optimValues.objective_available){display(optimValues.objective);}
    return 0;
}
Pass options(OutputFcn=monitor,OutputEvery=1) to the solver. The monitor can plot
current fitted models and bounded convergence history; return 1 to stop cleanly.
Ceres reports iterations, evolutionary methods generations, and NLopt/root methods
explicitly labeled evaluation updates. All solvers retain native objective/residual
callbacks. Observers run on the owner worker; immutable figures render on the GUI
thread. An observer may explicitly evaluate a native ODE model for visualization,
using its normal cost/budgets. No extra model evaluation is hidden by the monitor.

WORKFLOW AND LIMITS
New heavy kernels are lazy DLL/SO modules; existing numerical/algebra semantics,
thread budgeting, autosave, source safety and native cache reuse remain. The language
reference/help catalogue and F76-F86 contracts define exact bounded APIs. Each
category's README supplies expected results and limits. Unfinished subcases remain
unchecked in WORK_TO_DO.txt; a first implementation does not complete every broad
research milestone. Native Linux execution is not inferred from portable source.
