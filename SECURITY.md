# Security

For a suspected vulnerability, contact Dr Alireza Poshtkohi at
[a.poshtkohi@herts.ac.uk](mailto:a.poshtkohi@herts.ac.uk). Include the affected
version or commit, operating system, minimal reproduction and expected impact.
Use public issues for ordinary defects; avoid disclosing exploit details or live
credentials before the maintainers have had an opportunity to review a report.

Do not send API keys, passwords, private keys, unpublished manuscripts or personal
datasets. Replace sensitive model/data files with a minimal synthetic example.
If a credential was exposed, revoke or rotate it through its provider; deleting
the visible text does not invalidate an already disclosed credential.

Studio scripts, native callback compilation, dependency bootstraps and exported
programs execute code. Review untrusted scripts and packages before running them.
The Copilot feature is optional; review the selected provider and context before
explicitly sending a request. Offline Help does not require a cloud account.

This is a research software project. No fixed support period, response time or
complete security audit is promised. Reproduce scientific results with recorded
versions, inputs and numerical settings, independently checking critical results.
